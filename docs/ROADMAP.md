# Roadmap и чек-лист доработок

План развития yaml-validator. Отмечаем выполненные пункты, релизы — по крупным блокам.

---

## 1. Правила и проверки

| # | Пункт | Описание | Статус | Релиз |
|---|-------|----------|--------|-------|
| 1.1 | **quoted-values** | Требовать кавычки для строковых значений (не только для ключей), как в yamllint `quoted-values`. | ✅ | v1.18.0 |
| 1.2 | **trailing-dots** | Запрет точек в конце строк (например `key: value.`). | ✅ | v1.18.0 |
| 1.3 | **Одна пустая строка между блоками** | Более строгое правило: ровно одна пустая строка между логическими блоками (сейчас есть только `forbid_consecutive_empty_lines`). | ✅ | v1.24.0 |
| 1.4 | **Индентация** | Настраиваемый шаг отступов (`style.indent_spaces: 2` или `4`), запрет табов (TabInsteadOfSpaces). | ✅ | v1.22.0 |
| 1.5 | **Явное правило для табов** | Отдельное правило `style.forbid_tabs` (или `allow_tabs`) вместо только проверки в common_errors. | ✅ | v1.26.0 |
| 1.6 | **Минимум пустых строк между блоками** | Параметр `min_empty_lines_between_blocks` (0 или 1) — гибче, чем только «ровно одна». | ✅ | v1.27.0 |
| 1.7 | **Колонка в ошибках длины строки** | Указывать колонку в ошибке при превышении `max_line_length`. | ✅ | v1.28.0 |
| 1.8 | **Запрет не-ASCII** | Правило `forbid_unicode` для ключей/значений (строгие ASCII-конфиги). | ⬜ | — |
| 1.9 | **Проверка BOM** | Ошибка или предупреждение при наличии BOM в начале файла. | ⬜ | — |

## 5. Дополнительные правила

| # | Пункт | Описание | Статус | Релиз |
|---|-------|----------|--------|-------|
| 5.1 | **Запрет алфавитного порядка** | Для K8s-манифестов, где важен порядок (metadata перед spec). Обратное `check_key_ordering`. | ✅ | v1.19.0 |
| 5.2 | **Настраиваемый порядок ключей** | Задание приоритетов в конфиге (`key_order`), а не жёсткий алфавитный порядок. | ✅ | v1.19.0 |
| 5.3 | **Длина имён ключей** | Правило `max_key_name_length`, ограничивающее длину названий полей. | ✅ | v1.19.0 |
| 5.4 | **Запрет значений по умолчанию** | Правило «не использовать ключ X со значением по умолчанию» (например, для K8s). | ⬜ | — |
| 5.5 | **Уникальность элементов списка** | Проверка, что элементы массива (по выбранному полю) не повторяются. | ⬜ | — |
| 5.6 | **Регулярки для ключей/значений** | Правило «ключи или значения должны соответствовать шаблону» (например, для имён). | ⬜ | — |
| 5.7 | **Предупреждения (severity)** | Расширение модели: часть правил как warning с отдельным счётчиком и учётом в exit code. | ⬜ | — |
